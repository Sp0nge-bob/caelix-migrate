# CaelixFlow Server Migration & Auto-Deploy Tool (`caelix-migrate`)

Автоматический, безопасный и автономный инструмент миграции и развёртывания серверов экосистемы CaelixFlow (Debian 13 Trixie / Ubuntu 22.04+).

---

## 🚀 Быстрый запуск (одной командой)

Скрипт не требует предварительной установки зависимостей. На любом сервере запустите:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/Sp0nge-bob/caelix-migrate/main/migrate.sh)
```

Откроется интерактивное CLI-меню:

```text
╔══════════════════════════════════════════════════════════════╗
║             CaelixFlow Migration & Auto-Deploy Tool          ║
║   Автоопределение компонентов · Debian 13 · Без даунтайма    ║
╚══════════════════════════════════════════════════════════════╝

  1)  [PUSH]   Перенести этот сервер НА другой (указать IP)
  2)  [PULL]   Забрать данные СО старого сервера (указать IP)
  3)  [PACK]   Создать локальный .tar.gz архив (бэкап)
  4)  [UNPACK] Развернуть систему из локального архива
  5)  [SCAN]   Проверить, что будет перенесено (Dry Run, только аудит)

  0)  Выход
```

## 📋 Поддерживаемые компоненты (Автоопределение)

Скрипт автоматически сканирует сервер по сигнатурам и шаблонам:

| Компонент | Что переносится | Как развёртывается на новом сервере |
|---|---|---|
| **Vpn-Bot** | `.env`, код, горячий снимок `data/bot.db` (`sqlite3 .backup`) | Создание пользователя `vpnbot`, sudoers, `.venv`, `requirements.txt`, systemd (`vpn-bot-telegram`, `vpn-bot-web`) |
| **Vpn-Website** | `.env`, код | Развёртывание в `/opt/vpn-website`, `.venv`, systemd (`vpn-website.service`) |
| **MiddlewareJSON** | `.env`, код, снимок `data/middleware.db` | Развёртывание в `/opt/middlewarejson`, `.venv`, systemd (`middlewarejson.service`) |
| **Redis** | Наличие `redis-server` | Автоматическая установка `redis-server` и включение службы |
| **Nginx** | Конфигурации `/etc/nginx/nginx.conf` и `/etc/nginx/conf.d/*` | Установка `nginx` и `libnginx-mod-stream`, проверка `nginx -t`, немедленная остановка службы (`systemctl stop nginx`) для освобождения 80 порта |
| **Copyparty** | Файлы `/opt/copyparty` (или `~/copyparty`): `copyparty`, `copyparty.conf`, `docker-compose.yml`, `hists` | Развёртывание в `/opt/copyparty` и запуск `docker compose up -d` |
| **SSH настройки** | `.ssh/authorized_keys`, `.ssh/authorized_key` и `/etc/ssh/sshd_config` (опционально по вопросу `[y/N]`) | Восстановление ключей и конфига с правами `600`, рестарт служб `ssh` и `sshd` |
| **3x-ui** | Обнаружение существующей панели | Интерактивное предложение запуска мастера Sanaei в конце работы |

## 🛠 Режимы работы

### 1. `[PUSH]` — Перенос на новый сервер со старого
Запускается на старом сервере. Скрипт запрашивает SSH адрес нового сервера (например, `root@194.87.1.2`), собирает горячие дампы, передаёт их по SSH на новый сервер и запускает развёртывание.
```bash
sudo bash migrate.sh push root@NEW_SERVER_IP
```

### 2. `[PULL]` — Забор данных со старого сервера на новый (Рекомендуемый)
Заходите по SSH на новый чистый сервер с Debian 13 и запускаете:
```bash
sudo bash migrate.sh pull root@OLD_SERVER_IP
```
Скрипт подключается к старому серверу, собирает архив, скачивает его на новый сервер, накатывает все зависимости и поднимает сервисы.

### 3. `[PACK]` — Создание локального архива (Бэкап)
Создаёт единый `.tar.gz` бандл со всеми базами данных, конфигами и исходниками:
```bash
sudo bash migrate.sh pack /root/server-backup.tar.gz
```

### 4. `[UNPACK]` — Развёртывание из локального архива
Полная автоматическая установка окружения на чистом сервере из ранее созданного архива:
```bash
sudo bash migrate.sh unpack /root/server-backup.tar.gz
```

### 5. `[SCAN]` — Экспресс-проверка сервера (Dry Run)
Безопасный аудит в режиме только для чтения: показывает, какие компоненты найдены на текущем сервере и готовы к миграции. Ничего не изменяет и не останавливает:
```bash
sudo bash migrate.sh scan
```

## 🔒 Безопасность и приватность

- **0 секретов в репозитории**: в коде отсутствуют токены, пароли, приватные ключи и IP-адреса.
- **Горячие снимки SQLite (WAL)**: базы данных копируются через `sqlite3 <db> ".backup <dst>"` с последующей проверкой `PRAGMA integrity_check`, что исключает повреждение незавершённых WAL-транзакций.
- **Свободный 80 порт**: служба Nginx после установки на новом сервере сразу останавливается, чтобы встроенный ACME-клиент мастера 3x-ui мог без конфликтов выпустить сертификаты в `/root/cert/`.
- **Права доступа**: секреты `.env` восстанавливаются с правами `chmod 600`, пользователь `vpnbot` изолирован.
